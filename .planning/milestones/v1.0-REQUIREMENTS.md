| Adding new KPI/KRI modules beyond the four existing board metrics | The framework was what got built in v1, not the catalog |
| `enrich_vulns_with_assets` performance pass | Real fix is per-batch enriched-frame caching; deferred until module pattern stabilizes (v2 PERF-01) |
| Per-day cache wipe across midnight boundaries | Operational impact small; deferred (v2 PERF-02) |
| Building any of the 6 unbuilt reports listed in CLAUDE.md | Several may not be needed once the v1 framework lets analysts assemble equivalents from modules |
| Replacing WeasyPrint, switching SMTP libs, or any tech-stack swap | Stack is locked per PROJECT.md Constraints |

## Outcome Notes

**Adjustments to original plan:**
- Phase 3 grew from 6 plans to 7 due to UAT-discovered gap (Plan 03-07: pd.NA chokepoint at composer.py:1153 + tzinfo strip + .assign() pattern at 3 risk_score sites). The fix was test-first RED→GREEN; structural negative control via commit boundary.
- Phase 03 added quick task `rag-cell-width-shrink` (2 iterations) post-UAT to fix the unified-cover RAG strip wrap. Empirical bisect found WeasyPrint flex consumes ~33-37mm of phantom space; pinned 55mm with safety margin.
- Phase 4 D-04-05 baseline definition was REVISED before planning: structural-only (counts/booleans/sorted name lists), no metric values, no per-row data. Headline % drift daily with vulnerability churn — locking values would create false-positive alerts. Visual operator confirmation remains the human gate for value correctness; structural smoke is the SHAPE bar.

**No requirements dropped or scope-cut.** All 24 v1 requirements landed Validated.
