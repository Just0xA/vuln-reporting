<!-- These are the load-bearing facts DEPLOYMENT.md must encode. Pulled from Phase 7/9/10. -->

On-disk layout (/opt/vuln-reporting/):
  current -> releases/vX.Y.Z/        (symlink, atomically swapped by update_from_github.sh via `ln -sfn`)
  releases/
    vX.Y.Z/                          (extracted release, own .venv from pip install -r requirements.txt)
    .last                            (rollback breadcrumb — previous current target)
  shared/
    .env                             (operator-managed credentials — survives upgrades)
    delivery_config.yaml             (operator-managed — symlinked, NOT overwritten on upgrade)
    logs/                            (app.log, scheduler.log, update.log, warm_cache.log, delivery_log.db)
    output/                          (timestamped report folders)
    data/cache/                      (per-day parquet cache)
    data/trend/                      (trend snapshots)

Install path (production): download vuln-reporting-vX.Y.Z-slim.tar.gz + .sha256 from GitHub Releases.
  git clone is OUT OF SCOPE as a production install path (REQUIREMENTS.md) — document this explicitly.

Update flow (update_from_github.sh --version vX.Y.Z):
  download tarball + .sha256 -> verify SHA256 (refuse on mismatch) -> extract to releases/vX.Y.Z/
  -> create per-release .venv + pip install -r requirements.txt
  -> symlink shared paths (.env, delivery_config.yaml, logs, output, data/cache, data/trend) into release dir
  -> python run_all.py --dry-run (smoke) -> capture current target as .last breadcrumb
  -> atomic swap (ln -sfn) -> restart vuln-reports.service -> 10s settle -> systemctl is-active check
  -> auto-rollback if not active -> print rollback one-liner on success.

--check exit codes: 0 up-to-date, 1 update-available, >=2 error. Honors GITHUB_TOKEN (60->5000/hr).

Rollback one-liner (printed after every successful upgrade):
  sudo /opt/vuln-reporting/current/scripts/update_from_github.sh --rollback

Credentials in shared/.env: TVM_ACCESS_KEY, TVM_SECRET_KEY, TVM_URL; SMTP_*;
  GITHUB_RELEASE_REPO=owner/repo (required by --check); optional GITHUB_TOKEN.

systemd: deploy/vuln-reports.service runs /opt/vuln-reporting/current/ via EnvironmentFile
  /opt/vuln-reporting/shared/.env. Install: cp to /etc/systemd/system/, daemon-reload, enable, start.
</deployment_facts>
