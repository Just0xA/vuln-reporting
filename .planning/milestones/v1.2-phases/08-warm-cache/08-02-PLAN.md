<objective>
Ship `scripts/warm_cache.py` as the cron-friendly entry point that pre-fetches Tenable data into `data/cache/<date>/*.parquet`, mirroring the layout `run_all.py` already produces and consumes. The script reuses `tenable_client.get_client()` + the four `data.fetchers` functions verbatim — no extraction from `run_all.py`, no new dependencies (CACHE-02).

Purpose: Decouple Tenable fetch latency from report-run wall time. Operators run this on a cron schedule (e.g. 03:00 nightly); when scheduled groups fire later in the morning, every `data.fetchers` call short-circuits on `[CACHE HIT]` and report wall time drops to render time only.

Output:
- `scripts/__init__.py` (empty, makes `scripts/` a package so `python -m scripts.warm_cache` resolves).
- `scripts/warm_cache.py` with argparse flags `--date`, `--prune-stale`, `--verbose`, `--dry-run`.
- `logs/warm_cache.log` created automatically with `RotatingFileHandler` (5MB × 3 backups) matching the established pattern in `scheduler.py` / `reports/vuln_export.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cron scheduler → script process | Cron passes flags via argv; the script must log usage errors instead of dying silently to stderr. |
| Script → Tenable API | Authenticated TenableIO via `.env` credentials. Auth failure must produce a deterministic non-zero exit code. |
| Concurrent processes → cache dir | Daemon `run_all.py` and this script may overlap; atomicity is guaranteed by plan 08-01. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Repudiation | Cron failures invisible to operator | mitigate | LOG-01 + LOG-03: every invocation produces a "started" + "completed" line; argparse usage errors are caught and logged with the real reason before non-zero exit. |
| T-08-04 | Information Disclosure | Logging full `argv` could log secrets if operator passes credentials on the command line | accept | The script accepts only `--date`/`--prune-stale`/`--verbose`/`--dry-run` — none of these carry secrets. Credentials are read exclusively from `.env` per CLAUDE.md "Credential Management". Documenting "do not pass secrets via argv" is unnecessary because there is no flag that would consume them. |
| T-08-05 | Denial of Service | Unbounded log growth | mitigate | `RotatingFileHandler(maxBytes=5_000_000, backupCount=3)` caps total log footprint at ~20MB. |
</threat_model>
