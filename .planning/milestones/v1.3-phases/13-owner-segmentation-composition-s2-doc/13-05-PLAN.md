(1) **CR-01 (BLOCKER — flips Truth 3 to VERIFIED):** `reports/owner_supplemental.py:_build_owner_app_df` does `enriched.set_index("asset_uuid")[["owner","application"]]` (line ~110) without deduplicating first. `fetch_all_assets()` legitimately returns duplicate `asset_uuid` rows for multi-network/multi-hostname assets, so `.join(..., on="asset_uuid")` raises `ValueError: cannot reindex on an axis with duplicate labels`. The exception is swallowed by the fail-soft `try/except` in `board_summary.py:322-330`, returning `supplemental_excel`/`supplemental_csv` as `None` with no operator-visible signal. Fix: dedup keeping the first owner/application per uuid before `set_index`.

(2) **WR-05 (correctness — same root cause):** `data/trend_store.py:_count_by_owner` (line ~187-194) builds `dict(zip(enriched_assets["asset_uuid"], enriched_assets["owner"]))`, silently collapsing duplicate uuids to the last value — per-owner attribution becomes order-dependent. The total still reconciles, so `test_owner_counts_reconcile` cannot catch it; the production capture path passes a non-deduplicated frame. Fix: `drop_duplicates("asset_uuid")` deterministically before the zip.

(3) **WR-02 (correctness/consistency — reconciliation):** the supplemental "Open Findings" column is a plain `groupby(...).size()` over every row of `vulns_df` (the open+reopened export), over-counting vs the trend store's `open_findings_at` open set; the two artifacts from one run disagree. Fix: apply `open_findings_at(vulns_df, report_date)` before aggregating, threading `report_date` (board_summary already has `generated_at`) into `write_owner_supplemental`. Update the runbook only where the column-semantics correction requires it.
