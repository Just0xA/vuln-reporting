## Goal

Redesign the PDF cover and apply a consistent, configurable header/footer to every page of every PDF report.

## Delivered

A shared PDF chrome design system that any modular metric report inherits for free. The chrome lives in `reports/modules/pdf_chrome.py` and is wired through `ReportComposer` via a single optional `pdf_chrome=` constructor kwarg. Two slugs opt into chrome via the `_CHROME_AWARE_SLUGS` allowlist in `run_all.py`: the v1.0-shipped `board_summary` and the YAML-driven `composed_report` slug — meaning every future metric module added to a composed report inherits the chrome with **zero per-slug Python**.

## Key accomplishments

- **`PdfChrome` utility** ships a single design-system surface for every PDF report. Frozen `PdfChromeConfig` dataclass (`title`, `subtitle`, `generated_at`, `header_bg`, `logo_path`, `privacy_label`) feeds a `PdfChrome` class that emits CSS + header HTML + footer-separator HTML. Title-only fallback when `LOGO_PATH` is `None` or the file is missing (CHROME-CFG-03 silent-fallback, no log spam).
- **`position: fixed` chrome overlays** replaced margin-box backgrounds after UAT revealed that empty `@top-center` / `@top-right` boxes collapse to zero width and leave visible gaps. The fixed-positioned approach paints the full 15mm top strip and a 1px footer separator edge-to-edge on every page.

- **Modular-framework parity:** `composed_report` inherits chrome on the same seam. Adding a new `*_module.py` to a `reports: [composed_report]` group + `modules:` list gives it full chrome with zero per-slug code.

## Notable surprises

- **Empty margin boxes collapse in WeasyPrint.** The initial chrome design used `@top-left/-center/-right` margin boxes with backgrounds to paint the header. Boxes with `content: ""` (empty string) rendered zero-width, leaving white gaps next to the title. Pivoted to `position: fixed` divs with negative left/right offsets matching the page side margins — much more predictable, gives pixel control.
- **`pdf_subtitle` double-prefix bug latent in composed_report.** Once the cover template was changed to bake "Scope: " into the template itself, composed_report's pre-existing `pdf_subtitle="Scope: {cat} = {val}"` would have rendered "Scope: Scope: Production". Caught during the chrome-parity extension; fixed by switching composed_report to the value-only formatter.
- **`_format_scope_subtitle` circular import.** Both `board_summary` and `composed_report` are imported by `run_all` via `importlib`, so they can't import `_format_scope_subtitle` back from `run_all`. Inlined the 3-line helper in both consumers. Plan was to share via util module; defer until > 2 consumers.
- **Same-day end-to-end delivery.** v1.1 went from milestone setup (8:25 AM) through context, planning, execution, UAT cycle, and milestone closeout in a single day. v1.0 was 4 days; v1.1 was 1 day because the milestone was scoped tight (chrome + one consumer + framework parity) and the v1.0 module contract did most of the heavy lifting.
