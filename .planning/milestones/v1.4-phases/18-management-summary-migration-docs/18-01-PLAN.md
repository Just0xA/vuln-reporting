<objective>
Capture a structural smoke baseline from the CURRENT bespoke `management_summary`
render path AND lock the exact bespoke numerical outputs against a frozen
synthetic fixture — both committed BEFORE any migration code is written. This is
the QUAL-04 contract and D-18-10 gate 3 (structure) plus the review-approved
PER-METRIC parity gate (review HIGH changes #1 & #2, QUAL-02).

The structural baseline encodes the structural shape (section count, RAG cell
count, module presence, Excel tab names, email panel count) of today's bespoke
output so the migrated output can be diffed against it post-cutover. To keep the
pre/post diff apples-to-apples (review change #5), BOTH the bespoke capture (here)
and the post-cutover `_bundle` capture (Plan 04) go through ONE shared
structural-snapshot schema/adapter — a stable key contract committed in this plan.

The value golden locks the exact metric numbers the BESPOKE path produces against
a small deterministic synthetic fixture (vulns + assets + fixed_vulns + a frozen
trend_snapshots.json), so Plan 04 can run the NEW modular path against the SAME
fixture. CRITICAL (review HIGH change #1, USER-APPROVED): the parity gate is
PER-METRIC, NOT a blanket zero-drift claim. Some metrics intentionally changed
semantics in the migration and exact parity for them is impossible/misleading.
The golden classifies each metric into one of two buckets (set derived from
18-RESEARCH.md Seven Module Definitions + the module docstrings — NOT assumed):

- EXACT-MATCH (semantics preserved → Plan 04 asserts zero drift, exact for integer
  counts / stated tolerance for floats): M1 total_vulns_by_severity (per-severity
  open counts), M2 scan_coverage_sla (coverage %), M3 mttr_trend (the rolling-30
  current-window MTTR value — D-18-06 preserves rolling-30), M4 patch_compliance_rate
  (compliance %), M6 accepted_recast (current-period accepted/recasted counts and
  exception rate; the MoM-delta sub-component is trend-sourced and is NOT part of the
  frozen-fixture exact assert).
- DOCUMENTED-DIFFERENCE (semantics intentionally changed → EXCLUDED from the exact
  assert; the golden records the bespoke value AND a written rationale of the
  expected difference, plus any shared invariant Plan 04 can still assert):
  M5 aged_vulns_assets — bespoke was an age-bucket HISTOGRAM OF VULNS; the module is
  "% of on-time-scanned ASSETS with a >90-day Med/High/Crit finding" (different unit
  and denominator → invariant:none; relies on the module's own tests + visual UAT).
  M7 new_vs_remediated — bespoke was a SIMPLE MoM total-open delta; the module is the
  richer inflow (net-new + resurfaced) / outflow (snapshot fixed_findings_count) trend
  with a net-delta (different metric; outflow is snapshot-sourced, not frozen-fixture
  derivable → invariant:none / document only).

Critically (review HIGH change #2): the fixture set MUST include
`fixed_vulns_df.parquet` AND a deterministic `trend_snapshots.json` — the
fixed-data and MoM metrics (mttr_trend, new_vs_remediated, indirectly
critical_remediation_sla, accepted_recast MoM) cannot be computed deterministically
without them, and without them the golden has FALSE coverage of the highest-risk
metrics.

D-04-05 reconciliation (review-approved, NOT a decision reversal): D-04-05
("structure locked, values NOT") governs LIVE-drifting values. The value golden
here is locked against a FROZEN SYNTHETIC INPUT, so it is deterministic and does
not depend on live data — a standard regression check, not a live-value lock.

Purpose: De-risk the highest-risk phase. The migration in Plan 04 cannot proceed
until both baselines exist — a baseline captured after migration code lands is
worthless as a regression guard (RESEARCH Pitfall 6), and the bespoke path is
ATOMICALLY REMOVED at the Plan 04 cutover, so the bespoke golden values (incl. the
documented-difference bespoke reference values) can ONLY be captured here while the
bespoke path still exists.
Output: `scripts/smoke_management_summary_cutover.py` + the shared structural-snapshot
schema + the committed structural baseline JSON + the frozen synthetic fixture set
(vulns + assets + fixed_vulns + trend_snapshots) + the committed bucketed bespoke
value golden JSON + the golden-capture script.
</objective>
