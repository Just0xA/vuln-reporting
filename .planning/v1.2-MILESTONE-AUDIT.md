## Gaps

### 🔴 B-01 (BLOCKER) — `ReadWritePaths` omits `shared/data/trend`
`deploy/vuln-reports.service:81` permits writes to `output`, `logs`, `data/cache` only. `reports/management_summary.py:243-246` writes `management_summary_*.json` into `data/trend/` (symlinked to `shared/data/trend` by `update_from_github.sh:444`) on every run. Under systemd's `ReadWritePaths` hardening the write is denied → any delivery group containing `management_summary` crashes under the daemon. **Fix:** append `/opt/vuln-reporting/shared/data/trend` to line 81. Affects FOOT-03/04, DOC-02.

### 🟡 W-01 (WARNING) — DEPLOYMENT.md inverts breadcrumb/swap order
`DEPLOYMENT.md:305-306` documents "capture `.last` (step 7) then swap (step 8)"; the code swaps then writes the breadcrumb (`update_from_github.sh:676→679`). Code order is the correct crash-safe invariant. **Fix:** swap steps 7 and 8 in the doc. Affects UPDATE-07, DOC-02.

### 🟡 W-02 (WARNING) — undocumented sudoers requirement
The updater calls `sudo systemctl restart vuln-reports.service` (lines 542, 692, 796). Run as the `vuln-reports` service account this needs a passwordless sudoers entry; neither DEPLOYMENT.md nor RUNBOOK.md documents it. Without it, restart fails for the non-interactive account and the health check auto-rolls-back every upgrade. **Fix:** document `vuln-reports ALL=(root) NOPASSWD: /bin/systemctl restart vuln-reports.service`, or document that the updater must be invoked as root (`sudo update_from_github.sh ...`). Affects UPDATE-05/08, DOC-02/03.
