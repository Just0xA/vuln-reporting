## Tech Debt (deferred — no blockers)

**Phase 12 — Trend Snapshot Substrate (S1)**
- **WR-01** — `open_findings_at` over-counts: a `state="fixed"` finding with `last_fixed=NaT`
  escapes all three `fixed`-mask clauses (each requires `lf.notna()`) and is returned as open.
  `utils/open_count.py:82-88`. Latent edge inherited verbatim from the Spike 002 blueprint.
  **Priority: resolve before any v1.4 report module consumes `open_findings_at` on live data** —
  the fetcher can produce `state="fixed"` with `last_fixed=NaT`.

**Phase 13 — Owner Segmentation + Composition (S2 + Doc)**
- **WR-01** — `owner_supplemental.py:100-105`: `asset_counts` built from the un-deduped `enriched`
  frame; `Asset Count` column over-counts physical assets that appear under multiple
  (owner, application) rows, producing phantom rows with `asset_count=1, open_count=0`. Affects
  column accuracy only; does not prevent file production.
- **WR-02 / pandas-3.0-CoW** — `owner_supplemental.py:128,129,139`: chained assignment violates
  the CLAUDE.md F-DTYPE `.assign()` convention. Fires `FutureWarning` today; under pandas 3.0
  CoW it will silently no-op, leaving `open_count` as float64-with-NaN. Fix with `.loc[:, col]`
  or `.assign()`.

**Total: 3 items across 2 phases.** All three are isolated to the trend/owner-supplemental
compute path and converge on a single follow-up plan candidate.
