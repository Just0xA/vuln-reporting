2. Add `resolve_python_bin()` (place it near other helpers, e.g. just after the
   Logger block or before provision_venv). Logic:
   - Prefer bare `python3` if `command -v python3` succeeds AND it reports >= 3.10.
     Check the version by running `"$candidate" -c 'import sys;exit(0 if sys.version_info>=(3,10) else 1)'`.
   - Otherwise iterate candidates in descending order: python3.13 python3.12 python3.11 python3.10;
     pick the first that resolves via `command -v` AND passes the same >= 3.10 check.
   - On success: set `PYTHON_BIN="$candidate"` (use the resolved path/name) and
     `log_line "resolved python interpreter: ${PYTHON_BIN}"`.
   - On failure (no interpreter >= 3.10 found): `log_completed "failed: no python3 >= 3.10 found on PATH; wire up python3 via 'alternatives --install /usr/bin/python3 python3 /usr/bin/python3.11 1' or install python3.10+"` then `exit 8`.

   add set +e regions; the `command -v` and version checks must be written so they do
   not trip `set -e` on the expected-miss path (guard with `if`/`||` as the existing code does).

3. In `main()` (line 837 block): call `resolve_python_bin` after `assert_layout`
   (line 867) and before `source_env`/dispatch, so logging is initialised and the
   interpreter is guaranteed for both check and install paths.

4. provision_venv() line 436: replace `python3 -m venv` with `"$PYTHON_BIN" -m venv`.

5. cmd_check() line 596: replace bare `python3` with `"$PYTHON_BIN"` AND remove the
   trailing ` 2>/dev/null` so interpreter/JSON errors land in update.log via the
   normal stderr path. Keep the surrounding `if ! latest=...; then ... exit 3` intact.
