gate (D-18-06, D-18-10 gate 1). The retention finding (30-day "wall" was an API

fixed-data consumer that previously relied on the implicit 30-day default. This

consumer — DYNAMICALLY discovering ALL callers (review change #3) — ensures each

widens the fetch only after the no-drift assertions are GREEN.

(CONTEXT specifics). The audit is a hard gate, not cleanup. Reconstruction
(Plan 03) depends on the widened fetch, so this gate must be GREEN first. The
live-API probe de-risks assumption A2 BEFORE Python logic is built on it
(Tenable export schemas are finicky; the ref doc can lag strict validation).
Output: live-verified filter shape + bounded fetch + dynamically-complete
consumer-audit test suite proving no metric drift.
</objective>
