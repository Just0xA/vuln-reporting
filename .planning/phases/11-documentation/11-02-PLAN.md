<cron_timing_facts>
<!-- The two hazards deploy/crontab.example must encode (from CLAUDE.md data-fetching guidelines). -->
- Cache folders are named by LOCAL machine date (YYYY-MM-DD), NOT UTC. A warm-cache run that fires near
  midnight risks writing to a date folder that the later report run won't read (date rolled over between them).
  Therefore: never schedule warm_cache.py near midnight.
- warm_cache must run ENOUGH ahead of the earliest report group that the fetch completes first — guidance ≥30 min.
- scheduler.py --mode run-due is the cron alternative to the systemd daemon: it runs only groups whose schedule
  matches within a ±10-minute window, so it must fire every 5–10 minutes.
- No live delivery_config.yaml is committed, so there is no concrete earliest-group time to read; the example
  must pick a sensible default earliest group (e.g. 07:00, matching the CLAUDE.md "Executive Team" sample) and
  schedule warm-cache at 06:15 — comment that the operator must adjust both relative to their own earliest group.
</cron_timing_facts>
