<objective>
Deliver the standalone cron entry point `scripts/capture_trend_snapshot.py` (D-09) that accrues the monthly `all_assets` severity snapshot without manual action. It mirrors `scripts/warm_cache.py` exactly — same logging skeleton, argparse subclass, exit-code conventions, and date-named cache reuse — and is the piece that makes trend history accumulate forward over time (the snapshot-not-reconstruction model; cold start is real).

The entry point does the fetching (D-08 division of labor): `get_client()` → `fetch_all_vulnerabilities(tio, cache_dir)` (state open+reopened) → `fetch_all_assets(tio, cache_dir)` → `capture_snapshot(df, assets_df, snapshot_date, "severity", "all_assets")`. It does NOT call `fetch_fixed_vulnerabilities` — the open-count predicate operates only on the open+reopened export.

Purpose: cron/Task-Scheduler-driven monthly capture so the substrate's trend series grows automatically; closes the loop so a second report calling `read_trend()` eventually receives a real month-over-month series.
Output: `scripts/capture_trend_snapshot.py` with `if __name__ == "__main__": sys.exit(main())`.
</objective>
