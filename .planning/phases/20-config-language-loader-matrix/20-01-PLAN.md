<objective>
Build the resolve-before-validate config loader — the spine of Phase 20. Introduce a new source language (shared `contacts.yaml` with named contact groups + a top-level `defaults:` block, and per-team `deliveries.d/*.yaml` files) and a resolver that expands `contact:` refs, `defaults.analyst_mailbox`, and additive `extra_recipients:` into today's concrete `email:` block — then hand the resolved effective config to the *existing* `delivery_config.schema.yaml` gate unchanged. Directory presence is the mode switch (D-01); legacy single-file mode is preserved for backward compatibility (QUAL-07).

The resolver ALSO exposes `owner` (team-file metadata) and the source `contact:` NAME for each delivery via a side-channel map keyed by delivery name (`metadata_by_delivery_name`). This map is returned SEPARATELY from the `{"groups": [...]}` object handed to the schema gate — because `delivery_config.schema.yaml` has `additionalProperties: false` at the group level (line 36) and stays UNCHANGED (D-09), so those keys cannot live on the group dict. The matrix generator (Plan 03) consumes this side channel for its owner + contact-name columns.

Purpose: CONF-01/02/03 are load-order sensitive and this plan implements them in order (contacts → defaults resolution → deliveries.d merge/uniqueness). Every downstream plan (dry-run surfacing, matrix generator, golden test) consumes this resolver.

Output: `delivery/config_loader.py` (new resolver module), `tests/test_config_loader.py` (unit tests), and a minimal edit to `run_all.py::_load_config` delegating to the resolver in directory mode while preserving the `list[dict]` return contract so `scheduler.py` hot-reload needs no edit.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-authored YAML → loader | `contacts.yaml` + `deliveries.d/*.yaml` are operator-authored config parsed at startup; malformed/hostile YAML crosses here |

| resolved config → schema gate | resolved effective config crosses into the existing Draft7 schema validator |

| T-20-01 | Tampering | YAML deserialization in config_loader.py | mitigate | Use `yaml.safe_load` exclusively (never `yaml.load`); acceptance criteria greps for bare `yaml.load(`. Mirrors existing run_all.py:172 pattern. |
| T-20-02 | Tampering | `deliveries.d/` glob discovery | mitigate | Glob restricted to `deliveries_dir.glob("*.yaml")` (no `..`, no absolute paths accepted); directory resolved relative to `config_path.parent` only, honoring the prod `shared/` symlink layout. |
