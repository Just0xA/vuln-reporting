<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-memory assets/vulns → data/trend/*.json (persisted) | Only aggregate owner counts may cross — no row-level fields |
| in-memory assets/vulns → output/owner_segmentation.* (asset-level) | May be emailed internally; MUST NOT be committed or sent to AI |
| Owner/Application tag value → Excel/CSV cell | Untrusted free-text could be a spreadsheet formula |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-07 | Info Disclosure | trend_owner_*.json payload | mitigate | new_entry holds only owner→count + month + tag_filter + asset_count + generated_at; test_owner_snapshot_no_pii asserts no hostname/ipv4/plugin_name/asset_uuid keys (TREND-06/D-11). |
| T-13-08 | Info Disclosure | owner_segmentation.xlsx/csv (asset-level) | mitigate | Written only under output/ (gitignored — `git check-ignore output/`); never under data/trend; not fed to AI/Claude context. D-10 permits internal email only; this plan does not attach it to email. |
| T-13-09 | Tampering | CSV/Excel formula injection via tag value | mitigate | Prefix any cell value starting with `= + - @` with a leading apostrophe before writing (RESEARCH §Security Domain); openpyxl writes values as data not formulas. |
| T-13-10 | Tampering | atomic write of trend_owner_*.json | mitigate | Reuse existing `_atomic_write_json` (temp-file + os.replace, Windows-safe) — no new write path (PATTERNS §Atomic JSON write). |
| T-13-11 | Denial of Service | supplemental error aborting board run | mitigate | write_owner_supplemental call wrapped try/except in board_summary — fail-soft, logs + None paths, never aborts the batch (Constraint). |
| T-13-12 | DoS | dimension=owner with no enriched assets | mitigate | Explicit ValueError on enriched_assets=None gives a loud, testable failure rather than silent all-zero counts (Pitfall 5). |
</threat_model>
