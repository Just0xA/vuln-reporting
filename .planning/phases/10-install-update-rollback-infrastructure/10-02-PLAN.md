       - `symlink_shared()` — takes `$TARGET_DIR`. For each of the six shared paths, runs `ln -sfn "${INSTALL_ROOT}/shared/<name>" "$TARGET_DIR/<name>"`. The six names, in this exact order:
         - `.env`

As of today, `data/fetchers.py` is a tracked source file so `data/` always exists post-extraction; this guard catches a regression.

         Use `ln -sfn` consistently — the `-n` flag prevents the "if target is a symlink to a dir, follow it and create the link inside" trap when re-extracting with `--force`.

       - `smoke_dry_run()` — takes `$TARGET_DIR`. Runs `(cd "$TARGET_DIR" && "$TARGET_DIR/.venv/bin/python" run_all.py --dry-run)`. DO NOT clear `PARTIAL_RELEASE_DIR` here — actually, on dry-run failure the operator wants to investigate the dir, so we want the trap NOT to delete it. Set `PARTIAL_RELEASE_DIR=""` BEFORE calling `smoke_dry_run`, so that even though we are still pre-swap, a dry-run failure leaves the release dir behind. Document this exception with a clear inline comment.

       - `atomic_swap()` — takes `$TARGET_DIR` and writes the new `current` symlink. Single command: `ln -sfn "$TARGET_DIR" "${INSTALL_ROOT}/current"`. UPDATE-06 forbids `rm -f current && ln -s …`. Verify post-swap that the symlink resolves correctly: `[[ "$(readlink "${INSTALL_ROOT}/current")" == "$TARGET_DIR" ]]`. Failure → log + exit 11 (this would indicate a permission or filesystem problem, not a corrupt swap — `ln -sfn` is atomic on POSIX).

       - `write_breadcrumb()` — takes `$PREV` (the previous `current` target captured before swap). Writes to `${INSTALL_ROOT}/releases/.last.tmp` then `mv` to `${INSTALL_ROOT}/releases/.last`. This makes the breadcrumb update atomic across a crash mid-write. UPDATE-07 step 2.

       ```

       symlink_shared "$TARGET_DIR"

         /*) ;;                                          # already absolute

Trust is anchored in the SHA256 sidecar, which is itself fetched from the same source — the integrity model is "we trust GitHub's TLS + repo access controls; the sidecar catches transport corruption and partial downloads, NOT a compromised GitHub repo." |
| `update_from_github.sh` → tarball contents | After SHA verify, the tarball is extracted as root into `/opt/vuln-reporting/releases/`. Any path-traversal entry (`../`) in the archive could escape. We rely on `tar -xzf … --strip-components=1` + the Phase 9 build-time `.gitattributes` boundary; we are NOT adding a runtime path-traversal scrubber (out of scope, accepted risk). |
| `update_from_github.sh` → systemctl | The script invokes `sudo systemctl restart vuln-reports.service`. Sudoers configuration (granting passwordless restart of this one unit to the update operator) is an install-time concern documented in Phase 11. |
