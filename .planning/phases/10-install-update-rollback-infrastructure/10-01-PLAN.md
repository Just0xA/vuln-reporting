  <files>scripts/update_from_github.sh</files>
  <action>
    Create `scripts/update_from_github.sh` as an executable Bash script. This task ships the scaffold and the read-only paths (`--help`, `--check`, `--list`); the `--version`, `--rollback`, `--force`, `--skip-restart` code paths are declared in the parser but their handler bodies are stubs that log `not yet implemented in plan 10-01` and exit non-zero (≥3). Plan 10-02 replaces the `--version` / `FORCE` stubs; Plan 10-03 replaces the `--rollback` / `--skip-restart` stubs.

    File contract (directive — implement in idiomatic Bash, not a literal paste):

    1. **Shebang + strict mode**: `#!/usr/bin/env bash` on line 1, then `set -euo pipefail` and `IFS=$'\n\t'`. This is UPDATE-09 — fail fast on any unhandled error.

    2. **Constants near the top of the file**:
       - `INSTALL_ROOT="${INSTALL_ROOT:-/opt/vuln-reporting}"` — allow override for testing on a sandbox path, default to the production location.
       - `LOG_FILE="${INSTALL_ROOT}/shared/logs/update.log"`
       - `SCRIPT_NAME="$(basename "$0")"`

    3. **Logger function `log_line()`**: takes one argument (the message). Writes `<ISO-8601-UTC> <message>` to `LOG_FILE`. Use `date -u +%Y-%m-%dT%H:%M:%SZ`. If `LOG_FILE`'s parent dir does not exist yet, create it with `mkdir -p "$(dirname "$LOG_FILE")"` before writing — the layout-guard check below ensures `INSTALL_ROOT/shared/` exists, but `logs/` underneath may be missing on a fresh install. Always `>>` (append). The function must never fail the script: wrap the write in a way that a write-failure logs to stderr but does not propagate (`{ ... ; } || true` is acceptable here — logging failures must not break operator commands).

    4. **`log_started` and `log_completed` helpers**:
       - `log_started`: emits `started at <ISO> with argv=<originally captured argv>`. Call it once after the early init block runs.
       - `log_completed <status>`: emits `completed at <ISO> status=<status>`. `<status>` is either the literal `success` or `failed: <reason>`.
       - Capture the original argv at script entry into a single string: `ORIG_ARGV="$*"`. This is referenced by `log_started`.

    5. **EXIT trap (UPDATE-09)**: install `trap 'on_exit $?' EXIT`. `on_exit()` receives the exit code:
       - If the script has already logged a `completed` line (track via a `COMPLETED=1` shell var set whenever `log_completed` is called), do nothing — avoid double-logging.
       - Otherwise the script is exiting due to an uncaught error: log `completed at <ISO> status=failed: trap-on-exit (rc=$1)`.
       - This plan's trap does NOT clean up release directories — Plan 10-02 extends the trap (or adds a sibling cleanup function) once extraction work exists. Leave a clearly marked comment `# Plan 10-02 will extend this trap with release-dir cleanup` inside `on_exit`.

    6. **Flag parser**: hand-roll a `while [[ $# -gt 0 ]]; do case "$1" in … esac; done` loop. Recognized flags (declare ALL six even though only two have real bodies in this plan):
       - `--check`              — sets `CMD=check`
       - `--list`               — sets `CMD=list`
       - `--version`            — sets `CMD=install`; requires next argv as `VERSION` (validate it matches `^v[0-9]+\.[0-9]+\.[0-9]+(-(rc|beta|alpha)[0-9.]*)?$`; reject otherwise as a usage error).
       - `--rollback`           — sets `CMD=rollback`
       - `--force`              — sets `FORCE=1` (no command on its own — orthogonal flag).
       - `--skip-restart`       — sets `SKIP_RESTART=1` (orthogonal).
       - `--help` / `-h`        — prints the usage block (see below) and exits 0 WITHOUT logging started/completed (help is the one exception — calling `--help` should not pollute update.log). Document this exception with an inline comment.
       - Any other argv         — usage error.
       Usage errors (unknown flag, missing value after `--version`, version regex mismatch, more than one command flag at once) MUST: (a) print a one-line `error: <reason>` to stderr, (b) call `log_started` + `log_completed "failed: <same reason>"` so the log records the real cause (LOG-02), then exit 2.

       Reject command-flag combinations that are nonsensical: e.g., `--check` + `--version` together is a usage error. `--force` is only meaningful with `--version`; if `--force` is passed without `--version`, log + exit 2. `--skip-restart` is only meaningful with `--version` or `--rollback`; same handling.

    7. **Help text** (printed for `--help`/`-h`): five-section block — synopsis line, brief description, flag table (one line each, two-space-aligned), three example invocations (`--check`, `--list`, `--version v1.2.0`), and a one-line pointer that this script's log lives at `$LOG_FILE`. Help is the script's primary discovery surface for operators.

    8. **Layout-guard function `assert_layout()`** (UPDATE-10): runs BEFORE env sourcing. Checks, with a distinct error message per failure mode (each error → `log_completed "failed: <reason>"; exit 2`):
       - `[[ -d "$INSTALL_ROOT" ]]` — "INSTALL_ROOT $INSTALL_ROOT does not exist".
       - `[[ -L "$INSTALL_ROOT/current" ]]` — "$INSTALL_ROOT/current is missing or not a symlink (refuse-if-unknown-layout)".
       - The resolved target of `current` (`readlink -f` or `readlink` then verify prefix) must start with `$INSTALL_ROOT/releases/` — "$INSTALL_ROOT/current points outside releases/ — refuse-if-unknown-layout".
       - `[[ -d "$INSTALL_ROOT/shared" ]]` — "$INSTALL_ROOT/shared/ missing — refuse-if-unknown-layout".
       Use `readlink "$INSTALL_ROOT/current"` (not `-f`) for the target prefix check; the comparison should accept both absolute (`/opt/.../releases/vX/`) and relative (`releases/vX/`) symlink targets — the existing Phase 7 systemd unit uses absolute, but tolerate either. Implement defensively: prepend `$INSTALL_ROOT/` to the target if it does not start with `/`.

       `--help` skips `assert_layout()` (so a fresh operator can still read help on a not-yet-installed host).

    9. **`--check` skips `assert_layout()`? NO** — `--check` does need to know the currently active version, which requires `current` to be a valid symlink. So `--check` runs `assert_layout()`. `--list` does too.

    10. **Env sourcing**: after `assert_layout()` passes, `source "$INSTALL_ROOT/shared/.env"`. Then assert `[[ -n "${GITHUB_RELEASE_REPO:-}" ]]` and fail with `"GITHUB_RELEASE_REPO not set in $INSTALL_ROOT/shared/.env"` if missing. `GITHUB_TOKEN` is optional — do not error on absence.

    11. **GitHub API helper `gh_api_get()`**: single argument is the path after `https://api.github.com` (e.g. `/repos/${GITHUB_RELEASE_REPO}/releases/latest`). Uses `curl -fsSL`, sets `Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28` headers, conditionally adds `Authorization: Bearer ${GITHUB_TOKEN}` only when `GITHUB_TOKEN` is set and non-empty (UPDATE-12). Emit the body to stdout; non-zero curl exit propagates via `set -e`. Important: pass `--retry 2 --retry-delay 2` so a transient TCP blip does not abort `--check`.

    12. **`cmd_check()` implementation (UPDATE-01)**:
       - `ACTIVE=$(basename "$(readlink "$INSTALL_ROOT/current")")` — strip any prefix path components, leaving e.g. `v1.2.0`.
       - `LATEST=$(gh_api_get "/repos/${GITHUB_RELEASE_REPO}/releases/latest" | python3 -c 'import sys,json;print(json.load(sys.stdin)["tag_name"])')` — portable JSON parse; Python is already a runtime dep.
       - If `gh_api_get` or the python parse fails (e.g. no releases yet), `log_completed "failed: could not fetch latest release tag from $GITHUB_RELEASE_REPO"` and exit 3 (reserved for upstream API failure — distinguishable from usage error 2 and layout error 2).
       - Print exactly two stdout lines: `active:  $ACTIVE` and `latest:  $LATEST` (two-space-padding for visual alignment).
       - Exit code:
         - `0` if `$ACTIVE == $LATEST` — print `status: up-to-date`.
         - `1` if `$ACTIVE != $LATEST` — print `status: update available`.
       - `log_completed success` in both cases (0 and 1 are both successful executions of `--check`; only an error fetching is a failure).

    13. **`cmd_list()` implementation (UPDATE-04)**:
       - `ACTIVE=$(basename "$(readlink "$INSTALL_ROOT/current")")`.
       - Enumerate `"$INSTALL_ROOT/releases"/*` directories only (`find -maxdepth 1 -mindepth 1 -type d` OR `for d in "$INSTALL_ROOT/releases"/*/; do …`). Do NOT list `.last` (the breadcrumb file, when it exists).
       - For each entry, print the basename. Append ` * (active)` to the line whose basename matches `$ACTIVE`.
       - Sort by version (use `sort -V` so `v1.10.0` sorts after `v1.2.0`).
       - Print `(no releases installed)` and exit 0 if the releases dir is empty (still a successful query).
       - `log_completed success`.

    14. **Stubs for not-yet-implemented commands** (so the dispatch table is complete and Plans 10-02 / 10-03 see clean function-replacement seams):
       - `cmd_install()`: prints `error: --version flow not yet implemented (plan 10-02 will land it)` to stderr, calls `log_completed "failed: cmd_install not implemented in plan 10-01"`, exits 3.
       - `cmd_rollback()`: same shape, references plan 10-03.
       Each stub is a separate `cmd_*` function — Plans 10-02 / 10-03 replace the function body in-place.

    15. **`main()`**: order is exactly:
       a. `ORIG_ARGV="$*"`
       b. Parse flags (no logging yet — usage errors during parse handle their own log_started/log_completed pair as described in step 6).
       c. If `CMD` is unset, treat as usage error: "no command flag given (try --help)".
       d. If `CMD=help`, print help and `exit 0` (no logging — already noted).
       e. `log_started`
       f. `assert_layout` (writes its own log_completed on failure).
       g. Source env (writes its own log_completed on failure).
       h. Dispatch: `cmd_check`, `cmd_list`, `cmd_install`, `cmd_rollback`.
       Call `main "$@"` at end of file.

    16. **`chmod +x scripts/update_from_github.sh`** is the responsibility of the executor — note this explicitly in the action ("After writing the file, run `chmod +x scripts/update_from_github.sh`").

    Style:
    - 2-space indentation, no tabs.
    - All function names lowercase_with_underscores; all "constants" UPPER_SNAKE.
    - Inline comments are sparing; reserve them for the non-obvious bits (the `--help` log-skip, the relative-target tolerance in `assert_layout`, the trap's "no double-log" guard).
    - No external deps beyond `bash`, `coreutils` (`basename`, `readlink`, `sort`, `mkdir`, `date`), `curl`, `python3`. All standard on Debian/Ubuntu/RHEL/Rocky.
    - Do NOT introduce `jq` — `python3 -c '...json...'` is the agreed portable parse.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator shell → `update_from_github.sh` | The script runs as root (writes `/opt/vuln-reporting/`, calls `systemctl`). All argv must be validated; usage errors must not be silently ignored. |
| `update_from_github.sh` → GitHub Releases API | Outbound HTTPS to `api.github.com`. Optional bearer token. Response is parsed as JSON. |
| `update_from_github.sh` → `/opt/vuln-reporting/shared/.env` | Sourcing the env file makes any shell expression in it executable. Operator-controlled; trusted by convention. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | Pre-existing malicious symlink at `/opt/vuln-reporting/current` pointing outside `releases/` | mitigate | `assert_layout()` enforces target-prefix check (UPDATE-10) before any operation runs. |
| T-10-02 | Information Disclosure | `GITHUB_TOKEN` leaked to logs | mitigate | Logger only records argv and status strings; token is never echoed. The token is consumed only in the `Authorization:` header to `curl`. |
| T-10-03 | Denial of Service | GitHub API rate-limit (60/hr unauthenticated) exhausted by a cron-style `--check` schedule | mitigate | UPDATE-12: documented `GITHUB_TOKEN` lifts the limit to 5000/hr. |
| T-10-04 | Tampering | JSON parse via `python3` evaluates arbitrary input | accept | Input is the response body from `api.github.com`; the parse is `json.load` (not `eval`), so an attacker would need to compromise GitHub or MITM HTTPS. Out-of-band threat. |
| T-10-05 | Repudiation | Operator runs an update and the failure has no audit trail | mitigate | LOG-02 mandates every invocation, including usage errors, writes started + completed lines to `update.log`. |
</threat_model>
