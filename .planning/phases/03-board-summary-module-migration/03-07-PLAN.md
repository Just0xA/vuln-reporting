**Pandas-3.0-safe pattern (D-CoW from pandas docs + project memory observation 303):**
```python
# BEFORE (chained assignment — warns on pandas 3.0)
df[col] = df[col].fillna(0)

# AFTER (Copy-on-Write safe)
df.loc[:, col] = df[col].fillna(0)
```
For the cited lines: in every case the immediate predecessor produces a fresh frame (via `.copy()`, `.merge()`, `.groupby().size().rename()`, `.sort_values().reset_index(drop=True)`, etc.). The warning is triggered by the `df[col] = ...` SETTER pattern under CoW — not the underlying frame ownership. Replacing the setter with `.loc[:, col] = ...` is sufficient; no additional `.copy()` is needed UNLESS the executor confirms (by re-running the smoke after edit) that a specific line still warns — in which case add `.copy()` immediately above it. Order of edit:

1. Try `.loc[:, col] = ...` only. Re-run smoke.
2. If a line still warns, prepend `df = df.copy()` immediately above it.

This avoids over-copying frames that don't need it.

**INFO note: `.loc[:, col] = .fillna(0).astype(int)` dtype semantics on the 3 risk_score setter lines** (board_report_utils:469, high_risk_assets:267, aged_vulns:262). When the existing column dtype is float64 (NA-tolerant), `.loc[:, col] = <int64-result>` may PRESERVE the existing float64 dtype rather than replacing it with int64 — the chained `df[col] = ...` setter REPLACED the dtype outright. This is a subtle CoW behavioural shift. Decision (per checker INFO 1): add a one-line acceptance check to Task 3 confirming the post-edit dtype on `bu_breakdown["risk_score"]` (and equivalents) is still int-coercible (`pd.api.types.is_integer_dtype`) — see Task 3 acceptance criteria. We are NOT preemptively switching to a `df = df.copy(); df["risk_score"] = ...` workaround because it loses the `.loc` uniformity and the dtype is consumer-tolerant (downstream rendering coerces via `int()` or `safe_int()`); but if the acceptance check fails, the executor MUST switch the 3 risk_score lines to the `.copy() + df["risk_score"] = ...` pattern to preserve the original int64 semantics and document the swap in the Task 3 commit body.
