<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewed repo commit → server config | The config copied to the server must equal a reviewed, CI-passed commit; drift = untracked change reaching prod |
| operator SCP/SSH transport | The manual copy is trusted transport; provenance verifies the placed file matches the merged commit |
| dual-source window → deliveries | During cutover both config forms are live; the wrong source silently winning would break traceability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-13 | Tampering | live config vs reviewed commit | mitigate | `stamp_config_provenance.py` records the source commit SHA + sha256 at copy time; `verify` detects any post-copy drift (hand-edit) and exits non-zero — the D-03 invariant that live == a reviewed commit |
| T-21-14 | Repudiation | untracked server hand-edits | mitigate | The RUNBOOK removes SSH hand-edit as the documented path; all changes flow through PR + CODEOWNERS + CI, giving auditors an approval trail; provenance verify flags any out-of-band edit |
| T-21-15 | Denial of Service | cutover delivery interruption | mitigate | QUAL-07 SC4 sequence: legacy stays live through one full dual-source cycle; D-04 auto-fallback keeps delivering if directory-mode fails; legacy retired only after a verified clean repo-sourced cycle |
| T-21-16 | Information Disclosure | provenance sidecar | accept | The sidecar stores only SHAs, checksums, and timestamps — no recipient content; safe (Hard Rule 2). Real config lives only in the private repo |
| T-21-17 | Spoofing | wrong active source | mitigate | The D-05 `--dry-run` active-source echo (Plan 21-01) lets the operator confirm the repo-sourced path is actually winning before retiring legacy — no silent wrong-source delivery |
</threat_model>
