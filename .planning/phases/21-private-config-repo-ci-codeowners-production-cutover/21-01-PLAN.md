<objective>
Extend the Phase 20 directory-mode loader in `run_all.py` so that when directory-mode
config (`deliveries.d/` + `contacts.yaml`) is missing OR fails to resolve/validate, it
falls THROUGH to the existing legacy single-file branch instead of `return []` (D-04),
and so that "which source won" is logged every run and echoed in `--dry-run` (D-05).

This is the automatic dual-source fallback that makes QUAL-07's zero-interruption cutover
possible: during the cutover window the server holds BOTH config forms, the loader prefers
the reviewed directory-mode config, and any resolution/validation failure silently keeps
deliveries flowing off the legacy file while logging a WARNING that names the active source.

Purpose: Foundation for the cutover (Plan 04) and the CI gate (Plan 02, which invokes `--dry-run`).
Output: Modified `run_all.py` (PUBLIC app repo) + extended tests.

**Repo target:** PUBLIC `vuln-reporting` app repo. This is the ONLY plan in Phase 21 that
edits public-repo Python. No real config is touched — synthetic `example.invalid` fixtures only.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewed config file → loader | Config placed on the server (reviewed repo commit or legacy hand-edit) is parsed and drives who receives email |
| daemon reload → loader | scheduler.py hot-reloads config on every cycle; a malformed config must fail-soft, not crash the daemon |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering | `_load_config` fallback path | mitigate | Fallback only reaches the legacy branch, which still runs the unchanged `delivery_config.schema.yaml` gate before returning groups; a tampered legacy file that fails schema returns [] (no delivery), never unvalidated groups |
| T-21-02 | Denial of Service | scheduler daemon hot-reload | mitigate | `_select_config_source` + `_load_config` stay pure/side-effect-free and return [] on total failure; a broken config degrades to zero deliveries, never an unhandled exception that kills the daemon |
| T-21-03 | Repudiation | active-source ambiguity | mitigate | D-05 logs exactly one line naming the winning source every run + echoes it in `--dry-run`, so "which config delivered" is always attributable during the dual-source window |
| T-21-04 | Information Disclosure | test fixtures | accept | All new fixtures use `example.invalid` synthetic identifiers (Hard Rule 2 / QUAL-05); no real recipients committed |
</threat_model>
