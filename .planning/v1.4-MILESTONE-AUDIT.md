### Warning-level findings (degraded-but-functional — no crash)

- **INT-WARN-1 — snapshot overwrite loses aggregate fields** (`reports/management_summary.py` ~L420-427, `data/trend_store.py` ~L481-488). management_summary's forward-write omits `on_time_asset_count`, `reopened/accepted/recast_count`, `mttr_*`, `sla_rate_crit_high`; `capture_snapshot()` writes `None` for omitted optional fields and overwrites any non-reconstructed entry for the same (month, tag_filter). If management_summary runs *last* in a month the cron already populated, those fields go `None` → next month, `new_vs_remediated` shows an outflow cold-start bar, `program_health` hits the structural Amber cap, `vuln_density` drops that denominator point. Reconstructed months are immutable (exempt), which is why the parity gate + operator UAT didn't surface it. Affects GEN-01, RPT-01, RPT-02, RPT-05, RPT-07.
- **INT-WARN-2 — recast expiry cross-check skipped for management_summary** (`reports/management_summary.py` ~L345-361). `accepted_recast` is composed but `recast_rules_df` is never fetched/forwarded (no `fetch_recast_rules()` call); the module logs a WARNING and skips the expiry cross-check → `pending_reeval` is always 0 for this audience. `composed_report.py` does this correctly via `_MODULES_NEEDING_RECAST_RULES`; the hardcoded `_MGMT_MODULE_CONFIGS` path bypasses that gate. Affects RPT-04, GEN-01.
- **INT-WARN-3 — missing frozenset co-edit gate test** (`tests/test_composed_report_kwargs_gates.py`). `_MODULES_NEEDING_FIXED_VULNS` lacks the exact-membership assertion the other two frozensets have. Maintenance blind spot. Affects SUB-03.

Root cause shared by WARN-1/2: management_summary's direct-wired ReportComposer call mirrors board_summary but does not replicate composed_report.py's gated fetch-side logic. Both designed-for paths live in composed_report.
